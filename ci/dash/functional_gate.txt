# The hosted functional gate: a named list, not the whole runner.
#
# One test per line: the seconds all of its registered variants took together on
# the hosted runner, the test, and what it guards. A bare name runs every
# registered variant of it (feature_pos_staking.py is --descriptors and
# --legacy-wallet), so its seconds are the sum of theirs.
#
# The functional lane of .github/workflows/build.yml starts these longest
# first, in the order of their seconds; equal seconds keep this file's order.
# test_runner.py starts tests in the order it is given them, and a long test
# that starts late holds the lane after everything else has finished: on
# 2026-11-07 p2p_unbacked_pos_headers.py, sixth in the hand-ordered list this
# file replaced, started seven minutes in and then ran 1600 s alone. The seconds
# need not be exact, only in the right order. Every run of the gate lists the
# measured ones in its summary ("Functional gate: recorded and measured
# seconds"); refresh a line when its test has grown or shrunk a lot. Recorded on
# push run 42371427370 (2026-11-07); the four tests #379 added, on its PR run
# 42406840902; wallet_combineoutputs.py, which the CJ1 change (no CoinJoin amounts in
# combining) touches, estimated from its local runs until its first hosted run;
# rpc_help.py and tool_wallet.py, which the command-line conversion fix brought
# into the gate, likewise; and wallet_multiwallet.py and rpc_getblockstats.py,
# which came in once they stopped assuming Dash's chain.
#
# Until the gate existed the workflow ran zero functional tests: the inherited
# integration runner was never wired into the workflow. Every regression that
# only test/functional covers -- proof-of-stake, the evodb recovery, the Q60
# switchover, the Sentinel layer, the peer protocol -- was guarded by hand. Two
# defects lived under a green CI because of it: feature_llmq_chainlocks.py
# failed with a TypeError on the tip for months (#226), and a new log category
# aborted the node at its first line (#228).
#
# The list is explicit and every entry says what it guards, so dropping one
# takes a line here that says why. Registered tests that stay out, each with the
# measured reason (this binary, four CPUs, --jobs=4):
#   feature_llmq_q60_switchover.py, feature_llmq_q60_dkg.py and
#   feature_dsl_enforcement_scale.py run 66 daemons each, raise
#   TEST_RUNNER_MAX_NODES themselves and would collide with the port stride of
#   a parallel runner -- which is also why they are kept out of test_runner.py's
#   lists;
#   feature_dsl_scenarios.py: 261 s, seven masternodes and a quorum under
#   injected faults, on its own nearly another chainlocks run;
#   feature_dsl_enforcement.py: 83 s, seven masternodes, the punishing branch
#   behind -testactivationheight=dslenforcement;
#   feature_dsl_faults.py: 71 s, seven masternodes with faults injected into a
#   running node;
#   feature_dsl_fault_injection.py: 9 s and two daemons, kept out because it
#   tests the fault injector itself, a lab instrument the node refuses to start
#   with outside regtest and devnet.
# From the same Sentinel layer the gate carries feature_dsl_service.py (the test
# that caught #228), feature_dsl_commit_decision_log.py and
# feature_dsl_commitment_v2.py: the probe, the producer's decision and the
# second bitfield, all live on the devnet.
#
# feature_dsl_commitment_v2.py was measured out of this gate once, and the
# measurement was right at the time: alone it passed three runs out of three,
# and in this company (--jobs=4 beside the chainlocks and staking runs) it
# failed three out of three. What it was failing on was not the runner but the
# node -- a receiver dropped an announcement that arrived more than one block
# ahead of the epoch base, which under load is where the announcements are --
# and that is now fixed (#235). Two halves of one lesson: a red gate on a timing
# race teaches people to ignore red, and a test that only fails under load can
# be reporting a defect that only appears under load. Re-measured on the fix,
# same four CPUs and the same list: three runs out of three green, the test
# itself 88/80/81 s, the whole gate 344/328/327 s wall.
